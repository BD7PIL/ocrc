# 逐组件视觉 / 动线评审

这张表就是"看过每个组件"的定义：**组件 × 状态**，每项一张截图。`scripts/audit.mjs`
按它驱动预览（真面板 + 真 kit + 假宿主），把图写到本目录。

```bash
node extensions/ocrc/scripts/audit.mjs            # 全套 30 张
node extensions/ocrc/scripts/audit.mjs --only 15  # 只跑序号含 15 的项
node extensions/ocrc/scripts/audit.mjs --no-serve # 复用已在跑的预览
```

每张图看七件事：**层次**（谁先说）、**对齐**（网格/列宽）、**折行**（长文本不裁切）、
**裁切**（不溢出）、**对比度**（深色也算）、**术语**（上游词，不夹内部机制）、
**动线**（下一步看得出来吗、破坏性动作有守卫吗、错误贴在哪）。

## 这一轮（第三轮）抓到并修掉的

| 级别 | 问题 | 证据 | 修法 |
| --- | --- | --- | --- |
| P1 | 操作台失败时日志不自动展开（`useState(phase==='error')` 初值在挂触时求值，挂触时多半还是 running） | 23 第一遍 | `useEffect` 盯 phase 变 error 才翻 |
| P1 | 操作台表头 spinner 与活动阶段行的图标重复且带出「进行中」文字 | 22 第一遍 | 表头去 spinner；spinner 移进活动阶段行的图标环 |
| P2 | 有新版时 hint 仍说「下一步：启动」误导主推 | 20 第一遍 | upgradeTo 时改说「可升级到 X，也可直接启动当前版」 |
| P2 | audit 弹层态拍照：`captureBeyondViewport` 触发 resize → SDK 菜单自拍前自闭 | 10 第一遍 | `popup: true` 项先量整页高设视口、普通截图 |
| P2 | console-running/chip 截图时序竞态（轮询往返慢于预设等待） | 22/24 第一遍 | 点击步支持 `after` 毫秒；chip 用 `jobdone` 场景一次轮询即 done |

## 已知的 P3（记录，不修）

- 操作台失败时卡片横幅与操作台横幅重复同一错误原文（两处都在是诚实；zcode 同款双落点）。
- 阶段轨道连线与图标圆心有 ~1px 舍入错位（7px vs 7.5px），视网膜屏不可辨。
- 「确认移除」是浅红底深红字的 light-destructive（宿主 kit 现行为，与 app 体系一致）。

## 测不到的（要真机）

宿主里真实的面板宽度、hover / focus ring、键盘 Tab 顺序、宿主自己的滚动行为、
真 job 的日志流速度——预览是假宿主，这几项只能你在 app 里点（升级链路的真机验收：
EL7 与 Ubuntu 各走一遍「检查更新 → 升级 → 自动重启 → 日志实时」）。
