# 0.20.0：左下角身份/设置区 + 上下文细分（opencode web 同款前端估算）+ 上轮批次收尾

## 背景修正（认账）
此前说"opencode 不暴露上下文分类"——API 层面属实（tokens 结构只有 input/output/reasoning/cache，已翻 1.18.32 fixture 证实），但 opencode web 的"上下文细分"（用户/助手/工具调用/其他）是他们**前端自己估算**的：按消息角色/类型分桶估 token，"其他"= 上下文总量 − 可归账残差（系统提示词/工具定义等）。结论：我们用同样的前端估算就能画出同款图，标注"估算"即是诚实。

## A. 上下文细分进圆环面板（ContextRing）
1. **估算器** `web/src/lib/inspector/contextBreakdown.ts`：输入 = 当前 feed 的卡片（用户文本/助手文本/工具 args）+ getContext 的 used/max；启发式 = 字符数÷4（中文按 ÷2 加权，实现取 `cjkCount*0.6 + other*0.25` 级别的保守估算）；分类 = 用户 / 助手 / 工具调用 / **其他（残差 = used − 可归账，clamp ≥0）**。
2. **ContextRing 弹层**加"细分"段：堆叠条四段（用户=info/助手=accent/工具=ok/其他=border 灰）+ 图例百分比——视觉对齐你截图里的 opencode 面板；标注"估算"小字。
3. 残差为 0 且无数据时整段隐藏（空会话不显示假数据）。

## B. 左下角身份/设置区（桌面 ≥821px，ZCode register）
1. 新增 `RailFoot.svelte`：左栏最底一行——enso 头像（首字母）+ 邮箱（截断）| 主题切换钮 + 机器人与通道钮（复用 toggleTheme/channelsOpen，零新状态）。
2. AgentPanel 加 `email` prop（layout 传入），在"活跃/已推送"行之下渲染 RailFoot；移动抽屉模式不渲染。
3. Titlebar 桌面隐藏三件套（加独立 class 精准隐藏）；≤820px 移动端**原样不动**。

## C. 上轮已实现未验收批次收尾（在工作树里）
中栏流式填满去居中限宽、会话头/输入区桌面改画布白（去灰横带）、性能三层（relay 120ms 流式合并、markdown 解析间隔自适应、历史卡 content-visibility）——本地测试已绿（483/125），补 CDP 视觉与 WS 帧数实测。
