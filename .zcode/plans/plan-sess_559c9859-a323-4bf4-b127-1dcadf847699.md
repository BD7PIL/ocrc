# 单仓定位 + 完整生命周期回归（守护以可选模式回归）

## repo 定位（裁决落定）
单仓 = **ocrc 遥控套件**：插件本体（运行时，opencode 进程内）+ 配套 CLI（人侧操作：install/pair/start/stop/…）。单版本列车，桥接与 dist 永不错位。运行时稳态 = 1 个 opencode 进程（内嵌插件）+ 可选的 1 个休眠级看护进程（99% 时间在 sleep 轮询，仅崩溃时动作）——对比 octg 三常驻件。

## 交付内容（全部在既有 src/cli/service.ts 上扩展，无新包无新仓）

1. **`ocrc start <dir>`（默认，现状保留）**：detached 一次性启动器（无守护）。
2. **`ocrc start --watch <dir>`（新增，run-4096.sh 语义的 Node 版）**：前台看护循环——
   - 探测端口已有实例则**接管**（adopt，不双启）
   - 子进程崩溃 → 延迟（OCRC_WATCH_DELAY 默认 5s）自动重启
   - 退出码 ≥128（SIGTERM/SIGKILL/stop 文件）= 主动停，不重启
   - `.stop-<port>` 标志文件优雅停机；SIGTERM 清理链（杀子进程 + 清文件）
   - 看护器自身 pid 写 `run/watch-<port>.pid`（stop 先杀看护器，由其清理链带走子进程）
3. **`ocrc restore`（新增）**：读 run/last.json 以 `--watch` 拉起，打印 @reboot cron 建议行（`@reboot sleep 60 && ocrc restore >> ~/.ocrc/prod.log 2>&1`）——用户要不要装 cron 自己定。
4. **`ocrc stop` 增强**：先查 watch pid → TERM 看护器（清理链带走子进程）→ 端口未释放再直接 TERM 子进程 → 兜底 SIGKILL。
5. **status** 增加 watch 进程行。

## 明确不做
多实例/`list`（单机单实例 + PRIMARY 选举，status 覆盖）、配置改写类功能——octg 的坟不复活。
