# 简化到 octg 水平：监督内建 + 砍看门狗层 + pending TTL 1 分钟

## octg 真相（归档源码核实，作为设计基准）
`octg start <dir> [web|server]` 一条命令 = 生成 run-<port>.sh 包装（内嵌 while 循环：接管已有实例/崩溃重启/.stop 文件优雅停机/TCP 探活）+ setsid 挂后台 + 写 pid 文件。**监督无条件内建，无开关**。stop = touch .stop + 进程组 TERM + 端口级强清。restore = 读 autorestore/<port> 记录、已运行跳过、逐个拉起。cron 仅可选 `@reboot restore`。无 list 之外的额外常驻件。

## 改动一：service.ts 对齐 octg（砍掉我们发明的复杂度）
1. **监督内建**：`ocrc start <dir>` 直接进入看护语义——CLI 检查端口 → 写 last.json → **spawn 自身**（`--supervisor <dir>` 隐藏参数，detached + unref，stdio 接 prod.log）→ CLI 退出；supervisor 进程跑现有 watchLoop（接管/崩溃重启/stop 文件/SIGTERM 清理，逻辑保留）。**删除裸启动模式与 `--watch` 旗标**（接受 `--watch` 但忽略，防老肌肉记忆报错）。
2. **单一 pid 文件**：`run/<port>.pid`（supervisor 的），删除 prod/watch 两种命名。
3. **stop**：TERM supervisor pid（清理链带走子进程）→ 端口未释放再直接杀端口 pid → SIGKILL 兜底（现有逻辑，去掉双 pid 文件分支）。
4. **restore**：幂等（端口在即 return）→ 读 last.json → 走 start。保留。
5. **status**：`server / supervisor / web / workdir` 四行（去掉 bare start 字样）。
6. **删除 watchdog.sh 与其 cron 行**（现处于暂停注释态，直接清掉）；恢复**唯一**的自恢复入口 `@reboot sleep 60 && ocrc restore >> ~/.ocrc/prod.log 2>&1`（octg 同款）。
7. 帮助文本收敛为：`start <dir> / stop / restart [dir] / status / restore`。

## 改动二：pending TTL 5 分钟 → 1 分钟
- `src/connectivity/pairing.ts:67` `DEFAULT_PENDING_TTL_MS = 60_000`（唯一实例化点不覆盖，全局生效）。
- 6 处硬编码文案同步：TG /pair（"within 1 minute"）、auth.ts ×2（"1 分钟过期或已被使用"）、PairGate 提示、ChannelsModal 提示、README 配对段。倒计时/过期判定/自动刷新均由 expiresAt 驱动自动适配，前端逻辑零改动。PairGate 落地页过期自动刷新已有——1 分钟寿命下自动刷新节奏刚好。
- docs/parity-audit 附录不动（历史记录）。

## 实施与验证
1. service.ts 重构 + pairing TTL + 6 处文案。
2. 单测：shouldRestart 语义不变；restore/start 的 supervisor spawn（mock spawn 断言 detached 自身调用）；TTL 单测改 60_000。
3. tsc + 双套件 + 双 build → commit → 发 **0.14.0**（CLI 行为变更，minor）。
4. 生产部署：npm i -g@0.14.0 → `ocrc stop`（清当前态）→ 用户终端 `ocrc start <dir>`（或我 setsid 拉起 + 你验收后自管）→ status/健康复验 → **落地页 1 分钟倒计时实测** → crontab 终态核对（仅 @reboot restore + cdp 行，无 watchdog）。
5. README 生命周期段同步（去掉 --watch 与 watchdog 描述）+ 记忆更新。

## 明确不做
- 不恢复 octg 的 list/multi-port/stop all（单实例 + status 覆盖）。
- 不做 mode 参数（web|serve 由 OCRC_SERVER_MODE 配置承载）。
