# 0.26.0：SSH 远程主机接入（自探测 · 自部署 · 官方 baseline）

## 定位与结论
- **ZCode**（zai-org/ZCode，Apache-2.0）远程连接的生命周期模式照搬：连接时 detect → 自动部署 → SSH 通道拉起 server，远端零预装；传输层用系统 ssh（零新依赖）。
- **老设备兼容 = ocrc 自己验证过的路，且只此一条**：官方 baseline opencode 在 glibc 2.17 (EL7) 上原生运行已被生产实证（本项目取代 octg musl 层的核心成果）。远端部署**官方安装、钉 1.18.x 族**——glibc 兼容与 ocrc 的 HTTP API 形状双重理由钉住。**不做任何 musl 兜底**——本功能完善后 octg/zcode 两个 legacy-glibc 仓库即退役删除。
- ocrc 侧复用：AgentBackend 已参数化（baseUrl+fetch）、registry/AgentPanel/会话列表多后端化、SSE 模板现成。

## 核心：远端生命周期状态机（每主机）
`unknown → detecting → provisioning → launching → online`；异常落 `needs-auth / error / offline`，面板实时显示：

1. **detect**（ssh exec 秒级）：`uname -s -m`、`ldd --version`（诊断展示）、`command -v opencode` + `--version`、远端服务端口是否在听、`~/.local/share/opencode/auth.json` 在否。
2. **provision**（仅当远端无 opencode）：
   - **官方 baseline 安装，钉 1.18.x**（实施时先核对官方安装脚本的钉版参数；装完 `opencode --version` 验证可执行）；
   - 远端无外网 → scp 本机二进制（同一官方产物，仅 `uname -sm` 与本机一致时）；
   - 都不行 → error 给明确原因与指引（不引入第三条安装路径）。
   - 安装输出环形缓冲，面板日志抽屉可看。
3. **launch**（一条 ssh 进程同时做隧道+起服务，进程死=全下线，无残留守护）：
   `ssh -N -o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -L 127.0.0.1:{本地口}:127.0.0.1:{远端口} [user@]host 'export PATH=...; OPENCODE_SERVER_PASSWORD={自动生成} {opencode路径} serve --hostname 127.0.0.1 --port {远端口}'`
   默认远端口 4199（避开用户自己的 serve）；密码生成后存 `remotes.json`（0600）；退出指数退避重启（cap 60s）。
4. **needs-auth**：远端无 auth.json → 面板给「同步本机凭据」（scp，显式动作）或手动 `opencode auth login` 指引。

## 集成（复用现有抽象）
5. **`src/core/remotes.ts`（新）**：`~/.ocrc/remotes.json` store（channels 模式 0600）——`{id, name?, host, port=22, user?, remotePort=4199, serverPassword?, enabled}`；API 响应脱敏。
6. **`src/core/remote-host.ts`（新）**：状态机 + inspect/provision/start/health；ssh 参数构造、provision 决策、状态迁移为纯函数（可测）；exec 输出环形缓冲。
7. **`src/core/agent/opencode-backend.ts`**：`OpencodeBackendDeps` 增 `fetchImpl?`（内部 ocFetch 调用点换 `xfetch`）与 `host?`；远程档 derates：`liveMirror:false`、`tuiSelect:false`、不挂 `getVcs/getVcsDiff`（本地 git exec 是唯一本地文件系统假设）。`oc-server-auth.ts` 抽 `buildBasicHeaders()`；远程 SDK client 用 `createOpencodeClient({ baseUrl, fetch })` 注入远端 Basic（SDK 原生支持）。
8. **`src/plugin/entry.ts`**：enabled remotes 注册 `remote:<id>` 后端 + 每远端 `/global/event` SSE（新 `src/core/remote-events.ts`，远端认证、3s 重连、帧喂 `dispatchEvent`——流式/sdelta/推送/权限全链路复用）。隧道未就绪 ping=false → 面板 offline，通了自动上线。
9. **API + 面板**：`routes/remotes.ts`（GET 脱敏 / POST / DELETE / toggle / `inspect` / `provision` 轮询日志 / `sync-auth`）；`server.ts` host 字段改 `backend.host ?? hostname()`。前端 **RemotesPanel**（照 SchedulesPanel：列表 + 状态机徽标 + 内联新建 + 两步删除 + 测试连接 + provision 日志抽屉 + 同步凭据），挂 Inspector 启动器第七卡「远程主机」；后端注册重启生效（channels 同款语义，面板提示）。
10. **测试**：store CRUD/0600/脱敏；ssh 参数与状态迁移单测；provision 决策（mock exec）；远程 backend derates + fetchImpl 注入；SSE 解析；路由测试；web vitest + tsc + 全量基线（490+）。

## 验证
- 生产 E2E：remote 指向 `127.0.0.1:4096`（跳过 provision 直达 launch）→ 第二后端出现 → 远端会话流式/工具/上下文/TG 全链路 → 删除清理。
- provision：单测 + 官方脚本钉版参数本地核对；真远端部署待你提供 SSH 主机时实测（或指定一台可达机器我来跑）。

## 明确不做
SSH 终端页签（下一批候选）；ssh2 应用内密码认证（BatchMode 密钥路线，面板引导 ssh-copy-id）；ZCode runtime 当 backend（如需要单独立项）；任何 musl/兼容层安装路径；远端版本漂移自动升级（detect 报版本差）；Windows 远端（WSL = 在 WSL 装 sshd 即普通主机）。
