# 裁决：配置差异真相修复（补链）+ 树状化 + 双向拉取 + 冷状态识别（2026-10-24，扩展 0.11.0）

## 背景

用户在差异卡上提出两连问：

1. 「点击配置同步后，非常久才会出现这个卡片，而且文件居然没有按文件夹树状同步和展开的选项？」
   ——探测慢（对端逐文件 spawn sha256sum，1.4 万文件分钟级）+ 展示是一堵平铺列表墙。
2. 「git 这块我有疑问，配置文件有专门的 git 跟踪？」——第一版计划里"拉回落点在 git 管理目录"的
   说法**没有核实就写了**。实盘复核推翻了它的一半：`~/.config/opencode` **不是** git 仓库；
   真正的仓库是 `D:\develop\OpenCodeConfig`，按条目软链入配置目录（opencode.jsonc、reeve、
   auth.json 三条已就位）。

顺着疑问往下挖出两个真问题：

- **链接清单第 4/5/6 条从未在本机创建**。关键的第 5 条 `~/.config/opencode/skills` 缺失，
  使 ocrc 的同步源里 skills 为空——EL7 整棵 14,064 文件的技能树被判「只在远程机器」，而其
  正主就在仓库 `.agents/skills`（抽样 sha256 逐字节同源）。14k 的 peerOnly 是幽灵。
- **「对端已被拉起，ocrc 却显示未检查」**（用户截图：app 直连 12ms 正常）。service 重启后
  内存态归零，卡片对 unknown 实例从不主动探测。

## 裁决（grilling 共识 + 用户补充需求）

- **动线与用途**：双向同步有两个动机——把对端演化的资产收编回控制端自用；经控制端 hub
  向其它机器扩散。会拉大库（整棵技能树级别）；落点进 git 管理目录（软链生效后拉取=写仓库
  工作树，commit 后成为正式声明）。
- **树状化**：三区共用一棵目录树，目录级勾选级联，<50 展开一层；「两边不同」行内方向切换
  （默认推，可切拉），整目录级联。
- **拉回**：范围=peerOnly（零冲突新建）+「两边不同」拉回方向；**对端覆盖本地必须先快照**
  （统一快照备份 `~/.ocrc/pull-backup-<ts>/<id>/`——git 只救得回已 commit 的）；配置文档
  （opencode.json/jsonc）不参与拉取；512MB 上限；拉取后 diff 自动刷新；一次显式确认（含
  覆盖时两段确认）。
- **忽略表**：每实例 `ignorePaths`，树上「忽略此目录」，diff/推送/拉取/CLI 同口径过滤；
  种子 `**/__pycache__/`（.pyc 运行垃圾，正是 diff 实测里唯一的真对端独有垃圾）。
- **冷状态识别**：service 启动对 enabled 实例 fire-and-forget 跑既有 probe()，5 分钟冷却；
  「下一步：启动」在观测过在线时改说「此前在线——启动会复用不重启」。

## 附记：软链纪律（这次踩出来的，今后照此执行）

- **链接的创建与接管归 OpenCodeConfig 的 setup-windows.cmd，ocrc 不做链接管理**——ocrc 只
  消费链接生效后的形态（同步源、拉回落点）。
- 软链进版本控制的文件必须本身被 git 跟踪：否则 fresh clone 缺文件、`git clean` 会吃掉活配置。
- 实盘清单与 setup-windows.cmd 的漂移要当真：`~/.agents` 整目录是一条符号链接（脚本里的
  第 4/6 条因此自动满足），别按脚本行数想象实盘。复查命令：`Get-Item <path> -Force | select
  LinkType,Target` + `git status --porcelain`（建链后仓库必须仍干净）。
- 探测提速的教训与手法：逐文件 spawn 在万级文件上是分钟级灾难；`find -print0 | sort -zu |
  xargs -0 -n50 -P4 sha256sum` + awk join 降到的 11.4s（EL7 实测），且 `?`（哈希不出）语义
  不变——「不可判定」永远不许伪装成「相同」。

## 明确不做

- 不做自动双向收敛/后台巡检；配置文档不参与拉取/对端覆盖；拉取不自动 commit；
- 不在 ocrc 里实现链接管理；不动 auth/凭据与升级链路。
