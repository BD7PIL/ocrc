# 无人值守开发计划：M9 通道配置（双端）+ M8 四命令（双端）

## 探索结论（已核实的底座）

- **M9**：配对 URL 构造器 `buildPairUrl` 已有；`qrcode@1.5.4` 已在依赖（`QRCode.toString(url,{type:'svg'})` 服务端出 SVG）；通道设置持久化照抄 `core/scheduler.ts` 的 schedules.json 原子写（tmp+rename+debounce）；web 弹窗照 NewSessionModal 模式（backdrop+ocrc-pop+manageFocus），入口加在 Titlebar themebtn 旁；TG 消费点：工具行隐藏在 `streaming-render.ts` 的 footer 组装处（`toolsSummary`），工作区过滤在 handlers 的 workspacesHandler。
- **M8**：`/file` `/file/content` 走 SDK 已有 `client.file.list/read`（1.17.13 自带）；`/skill`、`/experimental/worktree` 照 `selectTuiSession` 的 raw fetch 先例；响应形状已从 OpenAPI 快照核实（skill: {name,description,location,content}；file 节点 {name,path,absolute,type,ignored}；content {type,content}；worktree GET→string[]，POST {name?}→{name,directory}，DELETE→bool）；TG 分页照 renderSessionsMenu 的 cache+spage 模式；web 面板照 SchedulesPanel 模式。
- **通用**：能力位照 `suggestions?: boolean` 可选先例（acp/v2 不实现即自动缺省）；API 端点照 `registerSchedules(app, scheduler?)` 的可选卫兵模式；`/api/*` 全部走 auth（QR 端点在已配对会话内展示，安全模型与 /pair 一致）。

## 实施批次（提交粒度 = 阶段，每阶段全量测试+tsc+build 通过才提交；全程只做一次重启）

### 阶段 A：M8 四命令（TG + web 双端）

**A1 后端（opencode-backend.ts + backend.ts）**
- 接口加可选方法：`getSkills?(project)`、`listFiles?(project, path)`、`readFile?(project, path)`、`listWorktrees?(project)`、`createWorktree?(project, name)`、`removeWorktree?(project)`；capabilities 加 `skills/files/worktrees: true`（opencode，1.18.32 已核实端点存在；acp/v2 不实现自动缺省）
- 实现：file 两组走 `client.file.list/read`；skill/worktree 走 raw fetch `${baseUrl}/skill?directory=` 等（照 selectTuiSession 姿势 + 超时）

**A2 web 路由 + 客户端 + UI**
- `routes/m8.ts`：`/api/skills`、`/api/files?path=`、`/api/file/content?path=`、`/api/worktrees`（GET/POST/DELETE），薄代理到 backend
- client.ts 加 skills/files/fileContent/worktrees 方法
- Inspector 新增两个面板（照 McpPanel/SchedulesPanel 模板）：**SkillsPanel**（技能名+描述列表，只读）、**FilesPanel**（当前目录列表 📁/📄 + 点文件弹 content 预览模态，截断 800 字符 + "在编辑器打开"提示）、**WorktreesPanel**（列表 + 新建输入 + 两步删除，标 beta）
- 均挂 Inspector（skills/files/worktrees 顺序插在 SchedulesPanel 后），后续 TG 命令与这些面板共用同一 backend 方法

**A3 TG 命令**
- `/skills`：分页 inline 列表（名称+一句话描述，6/页，照 sessions cache+spage 模式）
- `/ls [path]`：分页目录列表（📁/📄、`..` 上级、路径越权校验=规范化后必须留在 activeWorkspace 内）；点文件 → 发预览卡（/file/content 截 800 字符，二进制 type≠text 拒绝）
- `/open <path>`：直接读文件预览卡
- `/worktree`：experimental 闸内——列表（`beta` 标注）+ 新建（等号语法 `/worktree = <name>`）+ 删除（两步确认）
- setMyCommands 数组补 4 条（29→33）；/help 文案同步

### 阶段 B：M9 通道配置（web + TG 双端）

**B1 后端**
- 新建 `src/core/channels.ts`：ChannelsStore，持久化 `~/.ocrc/channels.json`（原子写照 scheduler）。Schema：`{ bots: [{ id, channel: 'telegram'|'wechat'|'lark', enabled, credentials: {}, replyGranularity: 'standard'|'detailed', workspaces: 'all'|{ dirs: [] } }] }`；v1 每通道固定 1 个 bot 条目（tg-default/wechat-default/lark-default），不做新建/多实例

- entry.ts：创建 store 并注入 web opts + TG cfg（granularity getter、workspace 过滤 getter）

**B2 web ChannelsModal**（照 NewSessionModal 骨架：overlay/backdrop ocrc-fade/modal ocrc-pop/manageFocus/trapTab）
- 左侧通道列表（Telegram/微信/Lark + 状态点：已连接绿色/未绑定灰）
- 右侧详情：启用开关；Telegram 详情=关联机器人（token 输入脱敏 + 保存→写 channels.json 凭证，下次启动生效；显示"当前来自环境"）；微信/Lark=扫码占位卡（"待接入"状态 + 凭证表单预埋）

- 入口：Titlebar themebtn 旁新增"机器人"按钮（桌面）+ PlusMenu 项（移动端）；ui.ts 加 `channelsOpen` store

## 验证协议（无人值守自检）

每阶段结束：`tsc` 0 错误 → web vitest + 插件 vitest 全绿 → web build 成功 → git commit（阶段粒度）。
全部完成后：`scripts/spike-restart.sh` 一次重启 → 活体冒烟：curl `/api/skills`、`/api/files?path=.`、`/api/file/content`、`/api/worktrees`、`/api/channels`、`/api/pair/qr`（各验 200 与形状）→ TG 侧看日志确认 polling 存活 + setMyCommands 33 条成功 → ps 复核单实例。失败处置：重启脚本重试一次；TG 网络黑洞（无日志悬挂）按既有 runbook 再来一轮；连续两次阶段失败即停止该阶段并留档报告，不阻塞其他阶段。

## 风险与回滚

- `/experimental/worktree` 语义不稳定：全部包 capabilities 探测 + UI 标 beta；不触碰生产 4096（红线，只动 spike 实例）
- 大文件读取：/open 与 FilesPanel 预览一律截断；二进制拒显
- 通道凭证落盘：channels.json 权限 0600（照 token 文件先例）；token 输入 UI 脱敏显示
- 每阶段独立 commit，任何阶段失败可单独 revert；全程最多 2 次实例重启（阶段 B 后、全部完成后）
